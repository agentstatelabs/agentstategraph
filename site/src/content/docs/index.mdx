## The best substrate for agentic development

Every agentic system — whether it's running infrastructure, orchestrating research, writing code, or driving a multi-agent workflow — needs the same thing underneath: a place to keep state that agents can branch, reason over, govern, and be held accountable to. Today that need is met with ad-hoc JSON blobs, a dict in memory, or a database that has no concept of *why* a value changed.

AgentStateGraph is the missing layer. It gives any agent — and any fleet of agents — a content-addressed, branchable, blameable state store where **every change carries intent, confidence, authority, and provenance**, where speculation is O(1), and where what an agent is allowed to do is enforced by the data model rather than by convention.

## The vision

A future where AI is responsible for entire systems — infrastructure, codebases, research pipelines, ops — and is **accountable for them mechanically rather than socially**. Every change carries why, who authorized it, what alternatives existed, and what the agent expected vs. observed, across every branch, forever.

This is what the substrate has to look like when the primary actor is no longer a human who can be governed through PRs, code review, and Slack threads, but a fleet of agents that must be governed through data-model-enforced intent, confidence, authority, and blame. AgentStateGraph is that substrate.

## What it is not

AgentStateGraph is **not a Terraform replacement**. The Terraform-replacement space is crowded with evolutionary players, and the actor model is wrong: Terraform assumes humans writing HCL and opening PRs, while AgentStateGraph assumes agents making low-confidence decisions at scale and needing to be held mechanically accountable.

AgentStateGraph is **not a LangGraph helper**. LangGraph's `StateGraph` is an in-process Python dict with reducer functions, used inside a single agent's execution. AgentStateGraph is a persistent, content-addressed, branchable, blameable substrate used *between and above* agents.

AgentStateGraph is a **state primitive** — the layer on which a next-generation IaC tool, a next-generation GitOps tool, and agent-native ops tooling can all be built. *(If you landed here confused by the names, see the [comparison page](/compare/).)*

## Use It From Anywhere

- **MCP Server** — 73 tools, any MCP-compatible agent
- **Rust** — native library, 15 crates
- **Python** — PyO3 bindings
- **TypeScript/Node** — napi-rs bindings
- **Go** — CGo via C FFI
- **WASM** — runs in any browser, with per-call namespace support

**Storage backends:** in-memory, SQLite, Postgres (multi-tenant), and IndexedDB in the browser — the same API across every one.

## The Four Architecture Eras

AgentStateGraph sits at the bottom of a new architecture era. Each prior era needed its own primitives; this one does too.

| Era | Unit of Work | Key Primitives |
|-----|-------------|----------------|
| Monolithic | Function call | OS, filesystem, local DB |
| Batch / Request-Response | Request → Response | HTTP, REST, SQL, queues |
| Streaming | Event | Kafka, Flink, event stores, CQRS |
| **Intent-based** | **Intent → Outcome** | **AgentStateGraph** |

Agents don't execute linear scripts — they explore state spaces. They need a primitive that supports speculative branching, comparison, and merge with full reasoning history. Git is text-oriented. Databases lack branching. Event sourcing is append-only. AgentStateGraph fills the gap.
